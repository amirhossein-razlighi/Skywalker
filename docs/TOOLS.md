# Tool reference

Generated by `skywalker tools --markdown` (0.0.1). ✎ = modifies the scene (undoable, attributed to the caller).

## scene

| Tool | Description |
|---|---|
| `engine_info` | Version, renderer, play state, component types and tool categories. Call once at the start of a session. |
| `scene_overview` | Compact outline of the whole scene: every entity as one line (id, name, mesh/color, position, tags) in hierarchy order, plus environment and selection. Start here before editing. |
| `scene_query` | Find entities by name glob (e.g. "tree*"), tag, component, or proximity. Returns one line per match. |
| `batch` ✎ | Run many tool calls atomically as ONE undo step. If any operation fails, everything is rolled back and the failing index is reported. Use for building scenes efficiently. |
| `scene_save` ✎ | Save the scene as JSON (.sky.json). Path is relative to the project. |
| `scene_load` ✎ | Load a scene file (replaces the current scene and clears history). |
| `scene_new` ✎ | Start a new scene. By default it contains a ground plane, a cube and a camera; empty=true for nothing. |

## entity

| Tool | Description |
|---|---|
| `entity_get` | Full data of one entity: components (all fields), tags, vars, behaviors (intent + Wander source). |
| `entity_create` ✎ | Create an entity. Shorthands: mesh (primitive name), color, position, rotation (degrees), scale. `components` takes full component objects, e.g. {"light": {"kind": "point", "intensity": 3}}. Returns the new id. |
| `entity_update` ✎ | Change an entity. Only given keys change; component objects are merged field-by-field. Set a component to null to remove it. Example: {"entity": "Lamp", "components": {"light": {"intensity": 5}}}. |
| `transform` ✎ | Move/rotate/scale an entity. Absolute: position, rotation (degrees), scale. Relative: translate, rotate. space=world interprets position in world space even if the entity has a parent. |
| `entity_delete` ✎ | Delete an entity and all its children (undoable). |
| `entity_duplicate` ✎ | Copy an entity (with children, components and behaviors). Optional new name and position offset. |
| `component_schema` | JSON schema of components (transform, mesh, light, camera) and the environment, with field docs, ranges and enums. |

## render

| Tool | Description |
|---|---|
| `environment_get` | Current sun, sky, ambient, fog, exposure and grid settings. |
| `environment_update` ✎ | Edit scene lighting/atmosphere: sun (azimuth, elevation, color, intensity), sky colors, ambient, fog, exposure, grid. Optional preset: noon, sunset, night, overcast, studio (applied first). |
| `shader_get` | The renderer's current shader source (Metal Shading Language). Edit it with shader_set. |
| `shader_set` ✎ | Replace the renderer's shader source at runtime. On a compile error nothing changes and the compiler diagnostics are returned. Function names and struct layouts must be kept. |
| `perf_stats` | Frame cost and scene complexity: CPU frame-build time, draw calls, lights, entities, behaviors, assets and cached meshes. Check after big scatters or generators. |

## wander

| Tool | Description |
|---|---|
| `wander_reference` | The Wander behavior language guide (syntax, triggers, statements, functions). Read once before writing behaviors. |
| `wander_check` | Compile Wander source without attaching it. Returns diagnostics with line, column, code and hints. |
| `behavior_set` ✎ | Create or replace a named behavior on an entity: the natural-language `intent` (what it should do) and its Wander `source` (how). The source is compiled; by default code with errors is rejected and the diagnostics are returned so you can fix and retry. |
| `behavior_remove` ✎ | Remove a named behavior from an entity. |

## sim

| Tool | Description |
|---|---|
| `sim_control` ✎ | play / pause / stop the game, or `step` N fixed ticks (1/60 s each) deterministically and get the resulting logs and errors. stop restores the scene to its pre-play state. Use step + viewport_capture to test behaviors. |
| `sim_input` ✎ | Inject player input for the next ticks: press keys (fires `on key`), hold/release keys (for key()), click an entity (fires `on click`), or emit a named event. |
| `logs` | Recent Wander log output and runtime/compile errors. |
| `sim_trace` ✎ | Run the game for N ticks and sample properties over time — e.g. transform.position of the player, vars.score, mesh.color — to verify behaviors numerically (did it jump? does the score increase?). Paths: <component>.<field>[.<sub>], vars.<name>, name, enabled. By default the scene is restored afterwards if it was in edit mode. |

## view

| Tool | Description |
|---|---|
| `viewport_capture` | Render the scene and return a PNG plus every visible entity with its on-screen box [x, y, w, h]. annotate=true (default) draws each entity's #id on the image so you can match what you see to ids. Choose the view: the editor camera (default), the game camera (view="scene"), or any eye/target. |
| `viewport_pick` | Which entity is at pixel (x, y) of a capture with the given size (editor camera). Use with the boxes/annotations from viewport_capture. |
| `camera_set` | Point the editor camera (what the human sees and the default capture view). Use frame to fit an entity (or "all"), or set eye/target, or orbit with yaw/pitch/distance. |
| `selection_get` | Entities the human currently has selected in the editor ("this", "these" usually means them). |
| `selection_set` | Select entities in the editor to show the human what you mean. |
| `viewport_multi` | One image with four views of the scene (or an entity): perspective (top-left), top (top-right), front (bottom-left) and side (bottom-right). Orthographic views make layout, alignment and spacing problems obvious — use it to check level layouts. |

## history

| Tool | Description |
|---|---|
| `history` ✎ | Undo or redo edits (by anyone), or list recent history entries with who made them. |

## asset

| Tool | Description |
|---|---|
| `asset_import_mesh` ✎ | Import a mesh (.obj, .glb, .gltf — e.g. output of a 3D-generation model) and optionally assign it to an entity (its mesh becomes "asset:<path>"). Meshes are normalized to fit a 1m cube; glTF materials become a material asset. See also asset_import. |
| `asset_request` ✎ | Queue a request for generated content — kind: mesh (3D model), texture, sprite (2D), audio (sfx), music, video — with a prompt. A connected generator (image/3D/audio model) or an agent fulfills it with asset_complete; results are applied to `target` automatically. |
| `asset_requests` | List generated-asset requests and their status. |
| `asset_complete` ✎ | Mark a request done with the generated file (project-relative). mesh -> imported and assigned to the target; texture -> set as the target's texture; sprite -> target becomes a camera-facing textured quad. |
| `asset_list` | Search the project's assets (meshes, textures, materials, prefabs, scenes, audio...) by type, tag or text (matches path, description and tags; supports * globs). Each line shows path, type, tags, description and, for generated assets, the prompt that made them. |
| `asset_info` | Everything about one asset: GUID, type, tags, description, provenance, import settings, which entities use it, and type-specific data (material fields, prefab contents). |
| `asset_preview` | Render an isolated preview image of a mesh, material (on a sphere), texture or prefab — look before you place it. |
| `asset_import` ✎ | Register a file placed in the project (e.g. by a generator) as an asset. Meshes (.obj/.glb/.gltf) are imported — glTF colors/textures become a material — and can be placed as a new entity right away. |
| `asset_tag` ✎ | Set an asset's tags and/or description (and provenance). Good descriptions make assets findable by other agents later. |
| `asset_move` ✎ | Rename or move an asset file (its .meta and GUID move with it) and update every reference in the open scene. The file move itself is not undoable — move it back with another asset_move. |
| `asset_refresh` | Rescan the project folder for new or changed files (the editor also does this automatically). |
| `material_create` ✎ | Create a reusable material asset (*.mat.json): color, metallic, roughness, emissive (glows with bloom), albedo texture with tiling, unlit. Assign it with material_assign. |
| `material_update` ✎ | Change fields of an existing material; every entity using it updates instantly. |
| `texture_generate` ✎ | Procedurally generate a seamless PBR texture set — albedo, normal map and ORM (occlusion/roughness/metallic) — for realistic or stylized surfaces: bricks, planks, cobblestone, rock, rust, marble, fabric, scales, ... With create_material it also writes a ready material (triplanar by default, so it works on scaled primitives without stretching). Colors override the kind's defaults. The soft kinds `glow` (radial) and `curtain` (vertical rays fading upward) have transparent edges and make self-lit effect materials: particles, light pools, fake reflections, auroras, light shafts, steam. |
| `material_assign` ✎ | Use a material asset on one or more entities (sets mesh.material; empty string clears it). |
| `prefab_create` ✎ | Save an entity and all its children (components, behaviors, vars, tags) as a reusable prefab asset. Instantiate it with prefab_instantiate, scatter, or Wander spawn("prefab:path"). |
| `prefab_instantiate` ✎ | Create an instance of a prefab. Optionally drop it onto the surface below its position. |

## world

| Tool | Description |
|---|---|
| `raycast` | Cast a ray into the scene and get the first mesh hit (triangle-accurate): entity, point, surface normal and distance. Give origin+direction in world space, or a pixel x,y of an editor-camera capture (width/height). Use it to find the ground height, check line of sight, or aim placements. |
| `place_on_surface` ✎ | Move entities straight down (or up) so the bottom of their bounds rests on the geometry below them. Great after placing props roughly on uneven terrain. One undo step. |
| `scatter` ✎ | Procedurally place many copies of an entity or prefab in an area — forests, rocks, coins, crowds. Deterministic for a given seed. Random yaw/scale ranges, minimum spacing, and optional snapping to the surface below. All copies go under a new group entity; the whole operation is one undo step. |
